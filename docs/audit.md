# sticks audit (Phase 0)

Date: 2026-11-12. Audited against the working tree, which contains ~3,500
lines of uncommitted changes on top of `0.4.1` (`d1572de`).

## Module layout

- `src/main.rs` — clap CLI. Commands: `c`, `cpp`, `init`, `add`, `remove`,
  `src`, `update`, `feature` (`f`: list/deps/convert/add-pm/rm-pm),
  `config` (`cfg`), `test` (framework add/generate), `ci`, `target`,
  `docs`, `lint`. Bare `sticks` drops into an interactive menu.
- `src/lib.rs` — `create_project*`/`init_project*` orchestration,
  `configure_package_manager_build`, re-exports.
- `src/build_systems.rs` — `BuildSystem` (Makefile|CMake) + generators.
  CMake output is generated by `format!` string templates; Makefile output
  is generated per-language in `languages.rs`.
- `src/languages.rs` — `Language::{C,Cpp}`, Hello World sources, Makefile
  recipe text (uses `find`/`sort`/`uname`-style shell, `gcc`/`g++`).
- `src/dependency_manager.rs` (~1,600 lines) — universal `add`/`remove`/
  `list`. Detects `conanfile.{txt,py}` / `vcpkg.json` and edits manifests
  (conan INI `[requires]`, conanfile.py `requires =`/`self.requires`,
  `vcpkg.json` dependencies array with `name@version`/`>=` parsing).
  Falls back to Makefile `install-deps` + `LDLIBS` flag mapping or
  CMake `find_package`/`target_link_libraries`. Snapshots and restores
  files on failure.
- `src/features.rs` — build-system/package-manager detection and
  `convert`; `convert` already renames the old build file to
  `<name>.sticks.bak[.N]` instead of deleting it.
- `src/os_detect.rs` — system package-manager probing (apt/dnf/pacman/
  apk/zypper/brew/choco/scoop/nix).
- `src/updater.rs` — `sticks update`. **Currently refuses all automatic
  replacement** ("cannot verify GitHub release artifacts") after hardened
  install-path/version checks. Self-update is disabled pending M5.
- `src/file_handler.rs` — safe writes: `write_new_file` (create_new),
  `write_atomic`, `ensure_path_available`, project-name validation incl.
  Windows reserved names.
- Other modules: `build_config`, `cmake_parser`, `cmake_dependencies`,
  `makefile_parser`, `multi_target`, `package_checker`,
  `package_managers`, `sources`, `static_analysis`, `templates`,
  `test_framework`, `ci_cd`, `docs`, `interactive`, `constants`.

## File generation vs editing

- New files: generated from string templates (`build_systems.rs`,
  `languages.rs`, `templates.rs`, `package_managers.rs`, `ci_cd.rs`,
  `docs.rs`, `static_analysis.rs`, `test_framework.rs`).
- Existing files: line/block text edits (`dependency_manager.rs`,
  `build_config.rs`, `multi_target.rs`, `cmake_dependencies.rs`) or
  `serde_json` for `vcpkg.json`/`CMakePresets.json`. All writes go through
  `write_atomic`; edits are largely idempotent (dedup checks exist in the
  dependency paths).

## Platform specifics

- Makefile recipe uses `find ... | sort`, `uname -m` triplet selection for
  vcpkg — Unix-only. `gcc`/`g++` hard-coded (`languages.rs`,
  `templates.rs` `$gcc` problemMatcher, `ci_cd.rs` apt/dnf/pacman lists).
- CMake template hard-codes `-Wall -Wextra -Werror` in `CMAKE_*_FLAGS` —
  invalid for MSVC.
- `updater.rs` is already multi-OS (linux/macos/windows × x86_64/aarch64/
  armv7) with Homebrew/cargo/AUR/system-install routing.
- CI: `build.yml` runs tests on **ubuntu only**; `release.yml` already
  builds linux (x86_64/aarch64/armv7), macOS (x86_64/aarch64) and Windows
  binaries plus `.deb`, and produces `SHA256SUMS`.

## Suspected issues — verdicts

1. **Only x86_64 Linux + GCC supported** — *partially confirmed.* Release
   artifacts cover linux/macos/windows × x86_64/aarch64(+armv7 linux), and
   `os_detect` covers brew/choco/scoop. But generated *projects* assume
   GCC/Unix (`gcc`/`g++` in Makefile, `find`/`sort`, GCC-only warning
   flags in CMake, `$gcc` VSCode matchers). Confirmed for project
   generation; not confirmed for the sticks binary itself.
2. **`add` only edits `install-deps`, no manifest/version pinning** —
   *not confirmed.* `DependencyManager` writes `conanfile.*` and
   `vcpkg.json` with version constraints; `install-deps` is only the
   no-package-manager fallback. Version syntax exists
   (`name@version`, `name>=version` for vcpkg; `name/version@user/channel`
   passes through for Conan). Missing: `sticks add --system`, and no
   baseline/lockfile recording (`builtin-baseline`, conan lockfile).
3. **Conan/vcpkg require hand-editing** — *not confirmed* for `add`/
   `remove`; confirmed that initial `conan install`/`vcpkg install` and
   CMake toolchain wiring are manual (documented in manifests'
   install instructions; CMake toolchain block is auto-inserted).
4. **No `build`/`run`/`clean` commands** — *confirmed.* No such
   subcommands; generated Makefile has `run`/`clean` targets but sticks
   itself doesn't drive them; no `CMakePresets.json` except the Conan
   preset.
5. **`convert` deletes old build file** — *not confirmed.* It renames to
   `*.sticks.bak` (features.rs:132-154).
6. **`update` replaces binary without checksum** — *not confirmed as
   stated; worse in practice:* update is currently fully disabled with a
   clear error. M5 must implement verified download (SHA256SUMS already
   published by release.yml).
7. **README coverage claims inconsistent** — *not confirmed.* README has
   no coverage badge and no percentage; it says "229 automated tests"
   which matches `#[test]` count (229). `coverage.yml` exists but does
   not publish a badge. No hard-coded count conflicts found; the 44.58%
   figure does not appear in this tree.
